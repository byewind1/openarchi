# Wall edge pet palette: AC29 public-documentation research

Date: 2026-10-29. Scope: the user's two-row, five-column wall-edge palette screenshot. This note records public documentation and visible-image comparison only; no Archicad runtime interaction was performed by this research subtask. Target inherited from the existing [wall-editing contract](wall-editing.md): Archicad 29 INT, `29.0.0 v1 (5101)`, arm64. The online AC29 help is version-specific documentation, not proof of behavior of that installed build.

## Context and evidence boundary

The official [Wall Reference Line](https://help.graphisoft.com/AC/29/INT/_AC29_Help/040_ElementsVB/040_ElementsVB-7.htm) page includes [RefPalette.png](https://help.graphisoft.com/AC/29/INT/_AC29_Help/040_ElementsVB/RefPalette.png). Its two rows of five icons visually match the supplied screenshot. The same page documents that some wall pet-palette commands are available only when clicking the selected wall's reference line. This supports the palette's context and visible arrangement; the image alone does not establish every icon's name or operation.

[Pet Palettes](https://help.graphisoft.com/AC/29/INT/_AC29_Help/020_Configuration/020_Configuration-27.htm) documents select element → click editable edge/node/surface → choose command. Contents depend on element, clicked part and window. The active command can change before completion; completion dismisses the palette. P / Shift+P (Opt+P) cycle icons. Therefore this is a context-sensitive command palette, not one universal collection for every wall surface and view.

## Parameters and model implications

The [Tracker](https://help.graphisoft.com/AC/29/INT/_AC29_Help/030_Interaction/030_Interaction-40.htm) is contextual: Curve edge exposes Arc Radius; other operations use appropriate distance, angle or coordinate values. Numeric entry and Tab cycling are documented. A screenshot value such as 3737 does not independently establish the project's length units. OpenArchi currently stores metres; user-facing distance and thickness should follow its working-unit formatter. Rotation/tangent direction is angular input, while radius, displacement, elevation and thickness are lengths. Do not mix an absolute elevation with a signed elevation increment.

[Create a Trapezoid Wall](https://help.graphisoft.com/AC/29/INT/_AC29_Help/040_ElementsVB/040_ElementsVB-12.htm) confirms the relevant model distinction: a trapezoid wall is straight but its two end thicknesses can differ. Composite thickness variation belongs to the last core skin; if there is no core, to the thickest skin (last among ties). [Wall Reference Line](https://help.graphisoft.com/AC/29/INT/_AC29_Help/040_ElementsVB/040_ElementsVB-7.htm) restricts trapezoid reference-line locations to outside face, or core outside for a composite with core. This is plan thickness variation, not vertical wall slant.

Multiply supports Drag, Rotate, Elevate and Matrix actions. Its input methods distinguish jointly graphical spacing/count, fixed count with graphical increment, fixed spacing with graphical extent, and fixed count distributed over a total extent. The distribution “-1” option leaves a final empty interval. Drag/Rotate can use a picked path/arc. Vertical displacement and assigning Home Story by elevation are additional parameters. Elevate multiplication is available in Floor Plan and 3D. Any reduced OpenArchi implementation must name its supported modes explicitly instead of claiming full Multiply equivalence. [Multiply Elements](https://help.graphisoft.com/AC/29/INT/_AC29_Help/030_Interaction/030_Interaction-96.htm)

## Historical evidence for Top 4 and Top 5

The publicly accessible [ARCHICAD Essential Skills participant handout](https://www.rototype.org/pt/wp-content/uploads/pt/ARCHICAD_Essential_Skills_Handout_Participant_R02.pdf) identifies Graphisoft SE as its author/copyright owner, is dated 2020, and states AC23 INT training compatibility. This is historical first-party-authored documentation on a third-party host, **not AC29 runtime evidence**. Page 142 was read as text and rendered to inspect its diagrams; no proprietary image is copied into OpenArchi assets.

For Top 4, the diagram leaves the baseline straight while replacing the opposite contour by one sloped edge. The text specifies two contour points. For Top 5, the diagram shows a peak in the opposite contour and a new baseline node directly beneath it. The text specifies two tapered walls whose meeting thickness agrees. Their icons match the last two icons in the AC29 reference-line image. **Inference:** these functions have continued into AC29; exact numeric constraints and clicked-point handling remain unverified.

Proposed reversible OpenArchi geometry for Top 4: retain baseline endpoints A/B, construct the opposite edge through the two accepted points, and intersect that line with perpendiculars through A/B to obtain positive end widths. Reject a degenerate line, baseline crossing, non-finite widths or invalid host geometry. For Top 5: project the picked point onto A–B, split at an interior projection, use its signed perpendicular distance as the common new thickness, and retain original thicknesses at A/B. These mathematical rules are **OpenArchi implementation assumptions inferred from the historical diagrams**, not recovered Archicad algorithms. Keep the whole edit one cancellable preview/undo transaction. The original wall's hosted openings require explicit redistribution or rejection when crossing the split.

Per the current product decision, Top 3 may start from a straight wall using the start endpoint as its tangent anchor. This is an **OpenArchi extension/design choice**; AC29 public documentation describes nearest-endpoint tangent editing for arcs, and the exact straight-wall rule is still unknown.

## Bounded unresolved probes

1. On an isolated AC29 project, select a basic, outside-reference straight wall. Click the middle of its reference line. Capture the tooltip for top-row 3, 4 and 5. Repeat in 3D only if that view's palette is in scope. Record version and evidence IDs separately.
2. For Top 4, test whether it requests two independent points defining the opposite boundary, whether the reference line remains fixed, and whether both end thicknesses derive from that boundary. Record thicknesses before/after, cancel and undo. The two-click sequence is confirmed in the historical AC23 handout; its AC29 continuation needs verification.
3. For Top 5, test a point whose perpendicular projection is within the baseline, then an outside projection, then a point across the reference line. Determine whether the output is two independent tapered walls sharing a new thickness. Record IDs, reference lines and end widths. The shared-thickness result is documented historically; exact AC29 restrictions are **probe hypotheses**.
4. For Top 3, compare clicks near each endpoint of the same straight and curved wall. Confirm which endpoint anchors the tangent, whether endpoints remain fixed, and the zero-curvature/invalid-radius case.
5. For each implemented action, verify OpenArchi preview does not mutate committed state; cancel restores it; completion makes one undo step; undo/redo and save/reopen retain wall shape, openings and IDs as intended. These are OpenArchi acceptance requirements, not AC29 behavior established by the above pages.

No exact Archicad minimum radius, thickness range, group behavior, hosted-opening reassignment, lock handling, cancel-key sequence or undo transaction boundary was established by this bounded documentation review. Those remain unknown until observed or separately documented.

## Candidate reusable lesson (not yet approved for AGENTS.md)

- A wall-edge pet-palette icon can represent an edit to the wall's plan thickness distribution. Verify its tooltip and resulting model before mapping it to wall slant, height or polygon editing; a matching icon screenshot proves appearance/context, not the command's full geometry contract.
