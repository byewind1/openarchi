# 操作逻辑研究：判定方法与墙编辑案例

来源：2026-10-29 本轮开发复盘；用户明确要求沉淀技能与规则。只适用于 OpenArchi 的授权 Archicad 行为研究。具体结论不是全软件等价声明。

## 先判断在证明什么

把一个问题写成“某对象、某选择与视图中，某输入怎样改变状态/几何”。不要从图标直接跳到算法。需要分别回答：

- 命令身份与适用对象：基线/边线/节点、直/曲/梯形墙、多选、楼层、锁定和分组条件。
- 状态：未激活→临时激活或持久命令→已接受锚点→预览→提交/取消；记录按下、移动、释放、输入和 Enter 的顺序。
- 结果：元素 ID/数量、端点/厚度/高程、宿主关系、选择、撤销、保存重开。看起来相同不保证模型相同。

证据按主张逐项标记，而不是给整份文档一个“已验证”：

| 证据 | 可支持 | 不能单独支持 |
|---|---|---|
| 用户明确纠正 | OpenArchi 应达到的行为 | Archicad 已实测如此 |
| 截图/图标 | 当时可见布局、反馈、上下文 | 完整步骤、参数意义、几何算法 |
| 对应版本官方帮助 | 文档明确的适用对象和操作 | 未描述的边界/内部实现 |
| 旧版说明 + 新版相同图标 | 延续行为的假设 | 新版已确认行为 |
| AX、鼠标动作和前后捕获 | 实际走过的交互路径 | 未测量的精确几何/历史边界 |
| API 返回模型或显示多边形 | 该样本的可测输出 | 私有算法、任意设置的等价性 |
| 静态符号/调用关系 | 结构与候选路径 | 运行时调用、精确数值规则 |
| OpenArchi 代码/测试 | 自身实现及已测不变量 | Archicad 也如此 |

## 选择最小有效研究路径

1. `context <feature>` 后读专题契约的最新修正。旧 Ctrl 实现被 Cmd 修正覆盖；保留历史但明确失效，不让旧说明重新进入实现。
2. 用对应版本帮助解决已被文档回答的问题；只为剩余未知设计运行场景。普通源码分析不必绑定 REA。
3. 创建可丢弃项目或已保存文件的副本，记录目标版本/hash、实际进程/API端口/项目路径。多实例先核对端口，不能让探测写到用户实例。
4. 用最少构件改变一个变量：方向、宽度、参考线侧/偏移、端点顺序、交点位于端部还是内部。先正例，再选对结论最有区分度的反例；不要盲列菜单。
5. 操作前后保留请求、返回、模型和截图。AX 菜单/tooltip 定身份；连接器取精确数据；必要时用当前桌面输入能力完成缺失的拖动。Archicad 原生模态遵守 AX 优先规则。
6. 比较假设与观测，记录误差和反例。结果不符时先检查单位、参考线、材料、交接顺序及显示模式，再修改假设。不要先写“等价”再找截图背书。
7. 同条件捕获失败后换证据路径，只有目标/窗口等条件改变再重试。无 REA Evidence ID 时保留直接 API/AX 文件，不伪造、不借用其他场景 ID。

## 本轮可带走的真实结论

- **Trim**：Mac Cmd、点击最近交点之间区间有 AC29 文档支持；最新用户要求确定 OpenArchi 连续操作与临时快捷键。连续每次应从当前剩余几何重新计算。菜单持续到 Esc、端点边界最终段可删除等具体处理是本轮 OpenArchi 选择，未因此成为 AC29 新运行实测。对象子集及精确证据见[Reshape契约](../../../docs/features/reshape-toolbar/contract.md)。
- **十图标墙面板**：上排是节点、曲边、切线调弧、梯形墙外侧、梯形墙新点；下排拖动、旋转、镜像、升降、阵列。尤其最后两个上排图标不能误判为墙高/倾斜。梯形墙两命令在本轮依据旧版培训资料与图标对应，AC29 的完整步骤仍未实测。直墙起始切线锚点规则是 OpenArchi 扩展。见[证据矩阵](../../../docs/features/wall-pet-palette-research.md)。
- **铅笔、三档高亮、释放确认和多选节点联动**：用户明确指定的 OpenArchi 产品行为；自身 UI 测试/以往包的桌面检查不证明 AC29 的每个时序相同。三档反馈下的“候选在点击或回画布时晋升激活”也是本产品状态转换选择。
- **多墙收口**：AC29 INT 5101 的 Y/T/X 实测外轮廓与相邻射线+中心覆盖方案吻合；移位 T 有微小面积差，四墙锐角 Fan4 明显不同，且 AC 自身保留反向尖片。不能说“Archicad 永无突出”，也不能把按角邻墙计算写成已恢复的原算法。OpenArchi 为满足本次干净收口要求选择移除该尖片。见[测量、截图与差异](../../../docs/features/wall-junction-cleanup/contract.md)。
- AC29 文档中的材料优先级、Junction Order 只说明语义；本轮没有恢复完整材料/复合墙/顺序求解器。简单同材样本不能推广到这些情况。

## 几何比较怎样有判断力

API 的 floorPlanPolygons 可能是一墙多个显示图元。先求合并区域的覆盖和暴露边，再谈单墙所有权；三角剖分不同不等于外形不同。内部所有权不同也不能因 union 相同就断言单元输出完全等价。

只比较总面积会漏掉等面积的尖片与缺口。配合已知坐标、边界距离、中心覆盖、应为空点/应有体点检查；需要时比较轮廓。用顺序全排列、端点反转（同步参考偏置）、整体旋转、不同宽度、近共线和短墙两端交接检查不变量。正确锐角 miter 可以较长，不能以“距节点超过几倍厚度”一刀切判错。

本轮 union 面积（m²，0.3m宽、约4m射线）：Y120 AC 3.561028858 / 角邻方案 3.561028857；T 3.555 / 3.555；X 4.710 / 4.710；MovedT 3.424127964 / 3.424840430；Fan4 4.693368673 / 4.627269825。数值只属于契约中的这些坐标和设置，不能当通用验收常量。

## 仍应主动保留的未知

AC29 梯形墙两图标完整时序、直墙切线编辑的锚点规则；所有材料优先级和 Junction Order 的内部裁切；外置基线/同向重复射线的完整连接；曲墙、复合墙、不同高程异质交叠。给每个未知写下一次能区分假设的最小实验；不要用占位按钮或更漂亮的截图替代。
